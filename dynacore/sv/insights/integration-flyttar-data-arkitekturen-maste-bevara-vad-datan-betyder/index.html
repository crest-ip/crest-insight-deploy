Där ARC kompletterar ServiceNow

Del 3 av 5

Integration flyttar data. Arkitekturen måste bevara vad datan betyder

Verksamhetsplattformar är byggda för integration. ServiceNow har omfattande förmågor för att koppla samman information, sätta den i sitt sammanhang och styra den över systemgränser, bland annat genom Workflow Data Fabric och plattformens övriga integrationsmöjligheter.

Det gör information mer tillgänglig och användbar i arbetsflöden. Men när samma information används som underlag för ett arkitekturbeslut blir ytterligare en fråga viktig: har den betydelse som beslutet kräver överlevt kopplingen?

Ett värde kan lagras, tillgängliggöras eller synkroniseras korrekt samtidigt som en del av dess arkitektoniska sammanhang finns kvar någon annanstans: vem som stod bakom uppgiften, när den var giltig, vilken definition som användes, om den observerades eller härleddes och vad som ska hända när en annan auktoritativ källa säger något annat.

De dolda besluten i en koppling

Varje koppling mellan informationsmodeller innehåller arkitektoniska val, oavsett om de har dokumenterats.

En relation mellan många objekt på båda sidor kan bli ett enda fält. Flera livscykeltillstånd kan mappas till en mindre uppsättning kategorier. En tidsstämpel från källan kan förväxlas med tidpunkten för hämtning eller synkronisering. Ett objekt som beskriver ett föreslaget framtida läge kan se likadant ut som ett operativt faktum.

Kopplingen kan alltså vara tekniskt lyckad och ändå förändra den betydelse som är tillgänglig för ett arkitekturbeslut.

Fyra kontroller hjälper till att bevara betydelsen:

  • Spårbarhet till källan: var uppstod påståendet, och kan en granskare undersöka källan?
  • Tid: när var uppgiften giltig, när hämtades den och är den fortfarande tillräckligt aktuell för beslutet?
  • Kunskapens status: är den observerad, härledd, föreslagen, granskad eller godkänd?
  • Källansvar: vilken källa eller ansvarig person avgör när uppgifter motsäger varandra?

Kontrollerna behöver inte belasta varje rutintransaktion. De blir viktiga när information från flera källor används som underlag för att motivera en förändring med betydande konsekvenser.

Connect handlar om mer än anslutningar

ServiceNow har redan avancerade förmågor för att integrera och styra information. ARC syftar inte till att bygga ett parallellt integrationslager.

ARC behandlar den arkitekturfråga som återstår när ett beslut berör flera källor som var och en har ett legitimt informationsansvar.

ServiceNow kan bidra med portföljinformation och operativa uppgifter. Ett specialistrepository kan bidra med modellsemantik och relationer. Dokument kan förklara ett undantag eller ett arkitektoniskt motiv. En API-katalog kan ansvara för det kontrakt som en föreslagen förändring påverkar. Ansvariga människor kan fortfarande behöva avgöra tolkningar som inget system kan fastställa på egen hand.

ARC samlar det relevanta arkitektoniska sammanhanget kring beslutet och håller dessa skillnader synliga.

Det gör att arkitekturteamet kan resonera över källgränser utan att behandla varje anslutet värde som lika auktoritativt. Om två källor säger olika saker kan konflikten synliggöras för hantering. Om en slutsats är härledd kan den fortsätta vara tydligt skild från en observerad eller godkänd uppgift. Om källinformationen ändras ger spårbarheten ett underlag för att avgöra vilka slutsatser som kan behöva omprövas.

Målet är inte att bromsa integration. Det är att hindra kopplingar från att skapa en tillit som saknar grund.

ServiceNow blir mer användbart när informationen kan bidra till beslut som går över plattformens gräns. Specialistkällor blir mer användbara när de kan bidra med sammanhang utan att ge upp sin betydelse eller sitt informationsansvar.

Integration svarar på om information går att koppla samman och använda.

Arkitekturen måste också svara på om informationen fortfarande betyder det vi tror att den betyder när vi agerar på den.
